# Telegram Kids — что осталось реализовать

---

## ⚠️ ГЛАВНОЕ АРХИТЕКТУРНОЕ РЕШЕНИЕ: переход на GramJS

**Проблема текущей архитектуры:** весь медиатрафик (фото, видео, аудио, кружочки)
проходит через наш сервер дважды — это дорого и медленно.

**Решение:** встроить GramJS в мобильное приложение, чтобы оно само было Telegram-клиентом
и обменивалось медиа напрямую с CDN Telegram. Наш сервер становится только сервером управления.

### Новая архитектура после перехода

```
Мобильное приложение (React Native + GramJS)
        ↕ MTProto (сообщения, медиа — напрямую, наш сервер не видит)
    Серверы Telegram / CDN

        ↕ WebSocket (только события управления)
    Наш сервер (контроль, не прокси)
        ↕ Telegram Bot API
    Бот родителя
```

### Выбранная библиотека: GramJS

- **Репозиторий:** https://github.com/gram-js/gramjs
- **npm:** `telegram`
- **Лицензия:** MIT — бесплатно включая коммерческое использование
- **Стабильность:** ⭐⭐⭐ (community, не официальная; при обновлениях MTProto
  догоняет за дни; в React Native нужны полифиллы Buffer/crypto — решаемо)
- **Альтернатива на будущее:** TDLib через `tdl` — официальная C++ библиотека Telegram,
  лицензия Boost (бесплатно), стабильность ⭐⭐⭐⭐⭐, но сложная нативная сборка под iOS/Android.
  Целевой вариант для продакшн после MVP.

### Что нужно переписать

| Компонент | Сейчас | После |
|---|---|---|
| `api_server.py` | Telethon-прокси | WebSocket-сервер событий, Telethon убрать |
| `main.py` | Без изменений | Без изменений (бот родителя остаётся) |
| `db.py` | Без изменений | Убрать `settings(session_*)`, добавить `device_sessions` |
| `mobile-app/api.js` | REST-клиент | GramJS-клиент к Telegram + WebSocket к нашему серверу |
| Все экраны | Данные с нашего REST API | Данные напрямую из GramJS |

- [ ] **Шаг 1.** Установить GramJS + полифиллы в mobile-app (`npm install telegram`)
- [ ] **Шаг 2.** Создать `mobile-app/telegram.js` — singleton GramJS-клиент
      (аутентификация, хранение сессии в AsyncStorage, переподключение)
- [ ] **Шаг 3.** Переписать `LoginScreen.js` — авторизация напрямую через GramJS
      (убрать `/auth/request-code` и `/auth/verify-code` из api_server.py)
- [ ] **Шаг 4.** Переписать `ChatsScreen.js` — диалоги из GramJS, не с REST API
- [ ] **Шаг 5.** Переписать `MessagesScreen.js` — сообщения и медиа из GramJS напрямую
- [ ] **Шаг 6.** Переписать `ContactsScreen.js` — контакты из GramJS
- [ ] **Шаг 7.** Заменить REST на WebSocket в api_server.py — только события:
