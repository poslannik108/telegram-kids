# Telegram Kids — что осталось реализовать

## F — Мультиклиентная архитектура (частично готово)
Telethon-клиенты на каждого ребёнка уже создаются через `get_child_client()` в `api_server.py`
и кэшируются в `_child_clients[user_id]`. Нужно доделать:
- [ ] Graceful shutdown клиентов при остановке сервера (сейчас сессии просто бросаются)
- [ ] Обработка истечения Telegram-сессии (сейчас возвращает 401, нужно уведомить ребёнка)
- [ ] Переработать `start.sh` — запускать `api_server.py` и `main.py` как единый процесс
      (сейчас `api_server.py` делает `import main as backend`, но `main.py` не запускает
      event loop до вызова `asyncio.run(main())`)

## G — Отправка фото и файлов
- [ ] `POST /send-file` — принимает multipart/form-data, отправляет через Telethon
- [ ] `GET /messages/{chat_id}` — возвращать поле `media` (тип, URL превью, размер)
- [ ] В `MessagesScreen.js` — кнопка прикрепить файл (DocumentPicker) + отображение медиа

## H — Поиск чатов и людей
- [ ] `GET /search?q=...` — поиск по диалогам и контактам через Telethon
- [ ] В `ChatsScreen.js` поисковая строка уже есть в `ContactsScreen.js` — перенести паттерн

## I — Push-уведомления на телефоне
- [ ] Выбрать провайдер: FCM (Android) + APNs (iOS) или Expo Notifications
- [ ] `POST /device-token` — сохранять FCM/APNs токен устройства в БД (новая таблица `device_tokens`)
- [ ] В `api_server.py` при получении нового сообщения — отправлять push через Firebase Admin SDK
- [ ] В мобильном приложении — запрашивать разрешение и регистрировать токен при логине
- [ ] Убрать поллинг каждые 5 сек в `MessagesScreen.js` после внедрения push

## J — Запись и передача аудиофайлов
